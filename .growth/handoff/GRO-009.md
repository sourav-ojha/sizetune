# GRO-009: Add an "increase image size in KB" tool and page (only if GRO-019 decides a method)

## Goal
Forms with a minimum size reject small files; autocomplete shows ten phrasings and the SERP has mid-size tools, no big platform. Keyword is P2: the engine avoids metadata padding, so build only after the owner records a method in GRO-019. Approved growth roadmap item (weeks 5-8).

## Acceptance criteria
- AC1: Given a photo below a form minimum, When the user sets a minimum KB, Then the output is at or above it using a documented, honest method
- AC2: Given the result, When shown, Then the page states how the size was reached and the real byte size
- AC3: Given the build, When verify:html and verify:privacy run, Then both pass

## Non-goals
- Nothing beyond this item. No publishing, posting, directory submissions, account creation or ads changes unless an acceptance criterion says so.

## Constraints and assumptions
- Evidence: inference, medium confidence. Sources: S-017 https://www.google.com/search?q=increase+image+size+in+kb+online; S-023 https://suggestqueries.google.com/complete/search?client=firefox&q=increase%20image%20size%20in%20kb; S-045 repo:.product/PRODUCT.md.
- Target keywords: increase image size in kb, increase image size in kb without changing pixels.
- Risk: Padding to fake size may violate product principles; some forms may reject padded files
- Design is open: explore it with the brainstorming skill before implementing.
